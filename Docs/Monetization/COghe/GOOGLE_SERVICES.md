## Ads behavior

- Existing placements/caps are unchanged: banner on Menu/Home/Victory only; interstitial after wins from win 6, at least 2 wins and 90 seconds apart, max 4/session and 10/day, quiet period after rewarded.
- Rewarded is opt-in. Credit is saved once immediately at Google's earned callback, before the full-screen ad closes. Closing early or a show error pays nothing.
- Test and development builds use the three official Google demo units, never the revenue units. This still exercises the native SDK/network.
- UMP refreshes consent each launch. A required privacy-options entry is available from Pause. No consent-form error bypasses `CanRequestAds()`.
- Transient UMP failures retry after 15/30/60 seconds, waiting while offline. A publisher/configuration error does not loop requests. The test tools label the native provider as `SDK ads`; the Editor's fake-ad switch does not claim to disable native ads.
- Preloads have exponential retry backoff, capped at 60 seconds; stale cached ads expire. Banner unloads outside its allowed pages. No Ads prevents forced formats, while keeping optional rewarded. Plus prevents all ad requests.
- Firebase failure, offline ads or no fill do not prevent gameplay. No API call runs in the physics loop.

## Level telemetry contract

| Event | When |
| --- | --- |
| `level_start` | A playable attempt begins, after intro/Boss tour. Retry starts a new attempt. |
| **`level_end`** | Exactly once on a real win/loss: `outcome=win` + `success=1`, or `outcome=lost` + `success=0`. Use this event as the canonical result. |
| `level_complete` / `level_fail` | Compatibility aliases of the same result. Do not add them to `level_end` counts. |
| `level_retry` | The player confirms retry, after a failure or a manual restart. |
| `level_abandon` | An unfinished attempt ends through restart, Menu, Home, explicit level change or a normal app quit. It is **not** a puzzle loss. |

Shared parameters: `level_id` / `level_name` (stable content ID), `level` (display order), `campaign` (save/catalog key), `attempt` (per-device count for this level), `attempt_id` (unique diagnostic ID), `duration_seconds`, `replay` (already completed before this attempt), `outcome`, `reason`. Every Firebase event also carries `build_channel=test/store` and `event_schema=1`.

Active duration excludes Pause, modal popups, background/unfocused app and full-screen ads. Backgrounding does not split one attempt into two. Force-killing an app may leave a start with no end; do not invent a loss for that case. Attempt counters reset if app data is erased/reinstalled. The app supplies no email, real name or custom personally identifying user ID.

Existing shop, unlock, Drops and ad events also flow through the same Firebase sink. Firebase supplies its standard session/app events. The pre-initialization event queue is bounded at 128; the SDK handles ordinary offline delivery once initialized. No custom backend, network calls per frame or server account keys are needed.

## Read difficulty reports

[Open GA4](https://analytics.google.com/analytics/web/#/a58477001p557269271/admin/customdefinitions/hub) · [Firebase project](https://console.firebase.google.com/project/coghe-57f21/overview)

Created seven **event-scoped dimensions**: Level ID, Level order, Campaign, Outcome, End reason, Build channel, Replay. Created two **event metrics**: Active play seconds (`duration_seconds`, seconds) and Attempt number (`attempt`, standard). `attempt_id` is intentionally not a report dimension because it is unique for every attempt.

For a level-results Exploration:

1. Filter `Event name = level_end`, the desired Campaign, and `Build channel = store` for production balancing; use `Replay = 0` to focus on first-clear difficulty.
2. Rows: Level order, Level ID. Columns: Outcome. Values: Event count, Total users, Active play seconds, Attempt number.
3. Per-attempt terminal win rate = win count / (win count + lost count). Mean active time = sum Active play seconds / matching event count. For attempts needed to clear, additionally filter Outcome=win before dividing Attempt number by matching event count.
4. Check `level_start`, `level_retry`, and `level_abandon` separately. A level may frustrate players into restarting without ever triggering a formal loss; win/lost alone misses that. Starts without ends are unfinished/abandoned sessions, not automatically failed puzzles.

Only aggregate a duration/attempt metric on one canonical event type: values also appear on compatibility aliases and retry/abandon records. Reports/custom definitions take processing time; DebugView is used for immediate integration checks. Debug-mode events are excluded from ordinary aggregate Analytics reports ([Firebase DebugView](https://firebase.google.com/docs/analytics/debugview)).

## Remote Config and reward hardening — 04/10

`COgheRemoteConfig` fetches with a one-hour SDK cache, sets in-app defaults and stages a validated snapshot for the next launch. Offline/failure/malformed snapshots preserve the last valid cache. It does not change an open offer. `economy_revision` and `economy_variant` accompany events and user properties. The clean-win bonus defaults to zero; no A/B experiment is automatically started.

The exported `remote-config.defaults.json` contains numeric defaults/prices, additive gift IDs and the `home_visit` Plus invitation policy. Core gift entitlements cannot be revoked. Ranges enforce the approved maximum ad pressure (from win ≥6, gap ≥2 wins/90 seconds, cap ≤4/session and ≤10/day).

Reward descriptors capture amount, stable transaction key, item/day before SDK presentation. The earned callback commits the wallet + ownership + paid key + daily cap in one local save. Native dismissal only refreshes UI; duplicates cannot grant again. A force-kill before the SDK delivers earned is not an earned reward and cannot be reconstructed without a backend/SSV.

Actual SDK opened callbacks count impressions for pacing. Show failure records `ad_fail`, no `ad_complete`, no cap consumption. `OnAdPaid` records `ad_revenue` with value/currency/precision/network/placement; this diagnostic event is separate from automatic Firebase `ad_impression`. Do not sum both sources as revenue. Production positive revenue and iOS are not verified by Android Google demo ads.

IAP products, receipt validation, refund/revocation and real Restore remain deferred to Play Console setup. Plus exclusive art and rewarded hints remain later feature work; no release claim includes them.
