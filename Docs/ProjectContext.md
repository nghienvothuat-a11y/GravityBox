# COghe project context

Unity **6000.3.19f1** (`ProjectSettings/ProjectVersion.txt`), namespace `GravityBox`, URP 17.3.0, Input System 1.17.0. Current verification target is the macOS development player, universal Mono; mobile performance remains a separate device gate. No platform or package upgrade is part of the chapter expansion.

The current work appends campaign positions/content IDs 31–40 to the existing integrated 30-scene campaign. Follow [level rules](COGHE_LEVEL_DESIGN_RULES.md), [Day Lab style](ArtDirection/COghe/STYLE_RULES.md) and the approved [chapter dossiers](LevelDesign/COghe/Sketches31-40/README.md). Acceptance: each authored solution works through ordinary commands, real simulation, all matter reunited before the final aperture, and 32 escaped particles at victory. Retry, lost-power recovery and route clearance are required checks.

Runtime is in `Assets/_Game/Venom/Runtime`; `VenomLevelController` owns the simulation, `VenomCampaign` commands/progress, `VenomCampaignMotion` surface routes, and `COgheMechanism` components their physical mechanisms. Levels are authored by the partial `VenomCampaignBuilder` using Unity APIs. `GenerateCampaign40` appends new scenes without regenerating 01–30. `CampaignScenePaths` selects the complete integrated build. Legacy scenes stay available to the regression tests. UI is IMGUI; input supports mouse/touch. Saves remain owned by `VenomCampaignSave` with stable content IDs; automation disables persistence during tests.

Quality gates: exact-version compile, complete EditMode and PlayMode suites with nonzero result counts, then `GravityBox.Editor.VenomCampaignBuilder.BuildMac`. Full solution tests use 120 Hz simulation and public control APIs; no moved tissue, forced open gates, or forced victory. Runtime screenshots and logs must identify the tested state. The baseline is 32 particles at 120 Hz. Mobile 60 FPS is a measurement target; memory/loading budgets and minimum device are not yet defined in the repository contract. No claim of mobile qualification follows from Mac results.

Primary risks for this chapter are temporary door anti-pinch/recovery, two-way transfer entry/exit, bridge dock seams, physical rail intersections, and maintaining three simultaneous operators through two outputs. New-player difficulty, touch on physical mobile hardware and thermal behavior remain unmeasured until those sessions occur.

## Onboarding pilot requested 24 September 2026

The approved progression plan begins with an isolated ten-level pilot. `COgheOnboardingBuilder.Generate` copies source slots `1,2,41,8,14,18,9,16,42,10` into `OnboardingPilot/COgheLearn01–10`, preserving content IDs and using a separate definition `SceneSequence` and `ProgressKey` (`coghe.onboarding.pilot.v1`). Production definitions leave the new key empty and retain `venom.origin.v2`. First two pilot lessons lock rotation and teach tap/visible-pane climbing; `COgheOnboarding` reads actual grasp, rail, exit and movement state for short hints and target/finger illustrations. It never changes physics or supplies commands. Boss has no solution guidance. Shared HUD/feedback now use content identity rather than obsolete ordinal assumptions.

`--onboarding` selects the pilot in Mac/Android build wrappers; Android has a separate application ID. The production sixty-level catalog is not reordered yet. See `COGHE_ONBOARDING_PILOT_2026_09_24.md` for the novice test sheet and `LevelDesign/COghe/ONBOARDING_PROGRESSION_DRAFT.md` for the complete candidate mapping and remaining lesson-design gates.
